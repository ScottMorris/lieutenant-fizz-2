The site is generated by `tools/progress-report/` from the repository, with the Python standard library, `git` and, when it is signed in, `gh`. This edition was built on {{generated}} from `main` at `{{head}}`; pull request and CI data were {{gh.source}}. The generator is adapted from Desk's progress report, which has the same author and licence.

## Where the data comes from

- **History.** `git log --first-parent main` gives the merge commits. A merged pull request is one that `gh` reports merged and whose head commit is reachable from `main`; its own commits run from the head of the pull request it was stacked on, or from `main`, to its head, and its size is `git diff --numstat` over that range. With no `gh` data, a merge commit whose subject ends in `(#N)` stands for pull request N.
- **The tree.** File counts, lines per package, `#[test]` declarations, the golden transcript, `M0_SCRIPT`, and the figures stated in `docs/PLATFORM.md`, `tools/check-dos.sh` and the CI workflow are read from the tree of `main` with `git ls-tree`, `git show` and `git cat-file --batch`.
- **Pull requests and CI.** `gh pr list --state all` (state, heads, the check rollup of each head, the merge commit) and `gh run list --branch main` (CI on each merge commit), always for `ScottMorris/lieutenant-fizz-2`. Signed out or offline, the generator reads `snapshots/gh.json` instead, and every page footer says which source it used.
- **Measured numbers.** What only a build can tell (the DOS replay's platform lines, the sizes in `dist/dos`, `PARITY ok`) lives in `snapshots/measured.json` with the commands and the commit.
- **The manual.** The Manual page renders `docs/MANUAL.md` from the working tree as it is, copies the images it references, and ends with a table that maps each of its sections to the checks in this archive, from `manual-evidence.json`; without the file, the contents show a "coming" row.
- **Captures.** `capture.py` takes the screenshots and the DOSBox transcript and records each in `media/captures.json` with what it shows, the command, the commit and the date: DOSBox Staging's window is grabbed from a virtual X server with ImageMagick, and the Web page from headless Chromium through the DevTools protocol, with real key events. Every figure that is drawn rather than captured is SVG generated from the data above.

## Shelves and tags

Every chapter ends with three shelves. An entry is *catalogued* only when it names its check: a merged pull request with CI green on `main`, a transcript compared line for line, a test in `tools/check.sh`, or a measured number with its command. It is *uncatalogued* when it is built and not verified in the way that matters, such as on real hardware. The *wish list* is planned work. State tags (merged, in review, in progress, planned) come from `gh`. A roadmap step marked done whose pull requests are not merged with CI green on `main` drops a shelf, and the build prints a warning. The prose follows [`VOICE.md`](repo:tools/progress-report/VOICE.md).

## Checks

`build.py --check` validates every page it writes: balanced tags, unique ids, one `h1` per page, every internal link and anchor, every chapter linked from the index, alt text on every image, every figure in the registry, every published image shown by some page, and every file in `media/` recorded in `captures.json` with how it was made. Building also refuses a measured DOS transcript or parity hash that disagrees with the golden file, a BIOS tick count that disagrees with the timer arithmetic, a path diagram that names code no longer in the tree, and an unknown placeholder in the prose. `tools/check.sh` runs the generator's unit tests and a dry run of the gatherer, which works in CI's shallow clone.

## Commands

```bash
python3 tools/progress-report/build.py --check                      # gather from git and gh, build dist/progress-report, check it
python3 tools/progress-report/build.py --offline --check            # the same from snapshots/gh.json
python3 tools/progress-report/gather.py --update-snapshot           # refresh snapshots/gh.json from gh
python3 tools/progress-report/capture.py                            # refresh media/ (after tools/check-dos.sh and tools/build-web.sh)
python3 -I tools/progress-report/tests/test_report.py               # the unit tests, the voice check among them
python3 -m http.server -d dist/progress-report 9000                 # serve the site locally
```

To add a chapter, write `chapters/NN-id.md` with its front matter, narrative, a `figures` block and the three shelves; it appears in the contents, the pager and the gallery. The chapters not yet written are listed in `pages/coming.json` and shown as "coming" rows. The site is published by hand as a private multi-file Artifact; the tool's README gives the steps.

## The shelves

### Catalogued
- The generator's tests and dry run are part of `tools/check.sh`, so the `check` job runs them on every pull request.
- `build.py --check` passes on the site built from `gh` and on the site built from the snapshot.

### Uncatalogued
- The published pages in a browser: the site was checked by serving it locally and reading the HTML, not by looking at it.
- Screen readers and keyboard use of the step-throughs and the gallery's filters.

### Wish list
- The data file published next to the pages, so the numbers can be audited without the repository.
